## 💼 Công việc đã thực hiện

### 1. Launch EC2 trong Public Subnet ⏱️ 1.5 giờ
- **Mô tả**:  
  Dựa trên VPC đã tạo thủ công ngày 31/10, tôi tiến hành launch EC2 instance trong **public subnet**, nhằm kiểm chứng:
  - Route Table đã gán đúng Internet Gateway
  - Subnet có khả năng cấp public access thực sự
  - EC2 có thể giao tiếp với Internet

  Các bước thực hiện:
  - Chọn **Amazon Linux 2 AMI**
  - Gán EC2 vào public subnet
  - Tạo và gán **Elastic IP**
  - Gắn Security Group tùy chỉnh (chưa dùng default)
- **Kết quả**:  
  EC2 khởi chạy thành công, có thể nhận public IP và sẵn sàng cho việc test kết nối.
- **Ý nghĩa học được**:  
  Việc EC2 “có public IP” **không đồng nghĩa** với việc truy cập được Internet — mọi thứ phụ thuộc vào **route table và security**.
- **Tools/Tech**:  
  AWS EC2, VPC, Elastic IP

---

### 2. Thiết kế và cấu hình Security Group ⏱️ 1 giờ
- **Mô tả**:  
  Tạo mới Security Group và cấu hình theo nguyên tắc **least privilege**:
  - **Inbound**:
    - SSH (port 22) chỉ cho phép từ IP cá nhân
  - **Outbound**:
    - Allow all traffic (default)
- **Kết quả**:  
  EC2 chỉ cho phép truy cập SSH từ đúng nguồn, đảm bảo an toàn cơ bản.
- **Nhận thức quan trọng**:  
  Security Group hoạt động như **stateful firewall** ở cấp instance — nếu inbound được cho phép, outbound response sẽ tự động hợp lệ.
- **Tools/Tech**:  
  EC2 Security Group, AWS Console

---

### 3. Kiểm tra SSH & Internet Connectivity ⏱️ 0.5 giờ
- **Mô tả**:  
  Thực hiện:
  - SSH từ máy local vào EC2
  - Ping và `curl` ra Internet
- **Kết quả**:  
  - SSH thành công
  - EC2 truy cập Internet bình thường
- **Ý nghĩa**:  
  Xác nhận toàn bộ chuỗi:
  **Local → Internet → IGW → Route Table → Subnet → EC2 → Security Group**
  đang hoạt động đúng như thiết kế.

---

### 4. Ôn tập Network ACL và so sánh với Security Group ⏱️ 1 giờ
- **Mô tả**:  
  Ôn lại Network ACL để hiểu vai trò trong kiến trúc mạng:
  - Stateless
  - Có thứ tự rule (rule number)
  - Áp dụng ở cấp subnet
- **So sánh rút ra**:

| Tiêu chí | Security Group | Network ACL |
|--------|----------------|-------------|
| Cấp độ | Instance | Subnet |
| Trạng thái | Stateful | Stateless |
| Rule | Allow only | Allow & Deny |
| Thứ tự | Không xét thứ tự | Có thứ tự |

- **Kết quả**:  
  Hiểu rõ vì sao trong thực tế:
  - Security Group dùng thường xuyên
  - NACL dùng cho kiểm soát tổng thể hoặc compliance

## 🚧 Khó khăn và cách giải quyết

### Vấn đề: Không SSH được vào EC2 lúc đầu
- **Biểu hiện**: SSH timeout
- **Nguyên nhân gốc rễ**:
  - Security Group chưa mở port 22 đúng IP
  - EC2 chưa có Elastic IP
- **Cách khắc phục**:
  - Rà soát lại inbound rules
  - Gán Elastic IP cho instance
- **Kết quả**:  
  SSH thành công
- **Bài học rút ra**:  
  Luôn kiểm tra **Security Group và Route Table trước**, tránh debug lan man
