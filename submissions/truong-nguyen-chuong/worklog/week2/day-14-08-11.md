## 💼 Công việc đã thực hiện

### 1. Cấu hình Spring Security & JWT ⏱️ 2.5h
- **Mô tả**: 
    - Tạo `JwtUtil` class để generate và validate JWT tokens (HS256 algorithm).
    - Tạo `JwtAuthenticationFilter` để intercept requests và validate token.
    - Cấu hình `SecurityConfig` với `@EnableWebSecurity`:
        - Disable CSRF (vì dùng REST API với JWT)
        - Cấu hình URL patterns: `/api/v1/auth/**` public, các endpoint khác cần authentication.
        - Cấu hình CORS (cho phép frontend NextJS ở `http://localhost:3000`)
        - Sử dụng `PasswordEncoder` với BCrypt.
    - Tạo `AuthenticationController` với `/login` endpoint.
- **Kết quả**: JWT authentication hoạt động cơ bản, test với Postman thành công.
- **Tools/Tech**: Spring Security, jjwt library, Postman.

### 2. Tạo JPA Entities ⏱️ 1.5h
- **Mô tả**:
  - Triển khai JPA Entities bám sát schema database đã thiết kế cho User Service.
  - Các entity chính:

    **`AccountEntity`**
    - Mapping từ bảng `account`
    - Các field chính:
      - `uuid` (UUID, primary key)
      - `email` (unique)
      - `passwordHash`
      - `role` (ENUM: `USER`, `ADMIN`)
      - `emailVerified`
      - `createdAt`, `updatedAt`
      - `lastLoginAt`
      - `mfaSecret`
      - `mfaEnabled`
    - Sử dụng:
      - `@Enumerated(EnumType.STRING)` cho role
      - `@PrePersist`, `@PreUpdate` để tự động cập nhật timestamp
    - Đây là **central identity** và chỉ được quản lý bởi User Service.

    **`AccountDisableEntity`**
    - Mapping từ bảng `account_disable`
    - Lưu snapshot account khi user bị disable / soft-remove
    - Cấu trúc field giống `AccountEntity`
    - Dùng để:
      - Audit
      - Rollback
      - Phục vụ compliance / security

    **`UserProfileEntity`**
    - Mapping từ bảng `user_profile`
    - Quan hệ **one-to-one** với `AccountEntity` (`account_uuid`)
    - Các field:
      - `firstName`, `lastName`
      - `fullName` (computed column – không set từ JPA)
      - `dateOfBirth` (validate min age 13)
      - `city`, `countryCode`
      - `avatarUrl`
      - `bio`
      - `interests` (JSONB)
      - `socialLinks` (JSONB)
      - `preferences` (JSONB)
      - `privacySettings` (JSONB)
    - Mục tiêu:
      - Tách profile để tối ưu query
      - Tránh load dư dữ liệu khi login/authenticate
  - Áp dụng enum + DB constraint (`CHECK (role IN ...)`) để đảm bảo tính nhất quán.

- **Kết quả**:
  - Entity mapping rõ ràng, đúng DB schema
  - Phù hợp với kiến trúc microservice
  - Dễ mở rộng MFA, admin module, và event-driven sau này

- **Tools/Tech**:
  - Spring Data JPA
  - Hibernate
  - Lombok
  - PostgreSQL (UUID v7, JSONB)

## 🚧 Khó khăn và giải pháp

### Vấn đề: Xác định ranh giới API public và authenticated trong User Service

- **Mô tả**:  
  User Service cung cấp nhiều API liên quan đến authentication và quản lý tài khoản (login, register, verify email, forgot password, update info).  
  Ở giai đoạn đầu, việc xác định API nào nên public, API nào bắt buộc phải có JWT chưa thật sự rõ ràng.

- **Ảnh hưởng**:  
  Nếu phân chia không hợp lý có thể:
  - Public nhầm API nhạy cảm (ví dụ: update info, change password)
  - Gây khó khăn cho frontend khi gọi API
  - Dẫn đến rủi ro bảo mật về lâu dài

- **Nguyên nhân gốc rễ**:  
  Tập trung vào việc làm JWT hoạt động trước, chưa dành thời gian hệ thống hóa lại toàn bộ API theo security boundary.

- **Cách giải quyết đã áp dụng**:
    1. Liệt kê toàn bộ API của User Service và phân loại theo mục đích sử dụng.
    2. Chia API thành 2 nhóm rõ ràng:
       - **Public APIs**: login, register, verify email, forgot password, reset password  
       - **Authenticated APIs**: update info, change password, get profile
    3. Áp dụng nguyên tắc *self-managed user*:  
       - User chỉ được thao tác trên chính account của mình thông qua JWT.
    4. Cấu hình Spring Security theo whitelist thay vì blacklist để tránh public nhầm API trong tương lai.

- **Kết quả sau khi giải quyết**:
    - Ranh giới bảo mật rõ ràng
    - Dễ kiểm soát và audit API
    - Thuận lợi cho việc mở rộng thêm role-based authorization sau này

- **Bài học rút ra**:  
  Security không chỉ là cấu hình framework, mà còn là việc **thiết kế API đúng ngay từ đầu**.  
  Việc xác định rõ API boundary giúp hệ thống an toàn và dễ maintain hơn.
