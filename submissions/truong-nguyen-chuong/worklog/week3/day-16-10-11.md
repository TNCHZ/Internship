### 1. Cấu hình Spring Data Redis & Test OTP Flow ⏱️ 2h

- **Mô tả**:
  1. **Cấu hình dependencies**  
     - Đảm bảo đã khai báo `spring-boot-starter-data-redis` trong `pom.xml`.
     - Redis được chạy local thông qua Docker để phục vụ OTP storage.

  2. **Cấu hình Redis connection**  
     - Thêm cấu hình vào file `application-dev.properties`:
       ```properties
        spring.data.redis.host=${REDIS_HOST:localhost}
        spring.data.redis.port=${REDIS_PORT:6379}
        spring.data.redis.timeout=60000
       ```

3. **Xây dựng OtpService**  
   - Triển khai service chịu trách nhiệm quản lý OTP và reset token thông qua Redis.
   - Các chức năng chính bao gồm:

     - `saveOtp(String key, String otp)`:
       - Sinh OTP gồm **6 chữ số**.
       - Lưu OTP vào Redis với key theo format: `otp:{email}`.
       - Thiết lập **TTL = 300 giây (5 phút)** cho OTP.

     - `saveResetToken(String email, String token)`:
       - Lưu reset token (dùng cho chức năng quên mật khẩu) vào Redis.
       - Mapping token ↔ email để phục vụ bước xác thực tiếp theo.

     - `getEmailByResetToken(String token)`:
       - Lấy email tương ứng với reset token từ Redis.
       - Sử dụng để xác thực yêu cầu reset mật khẩu.
       - Hỗ trợ debug và kiểm tra trạng thái token.

     - `getOtp(String key)`:
       - Lấy OTP hiện tại từ Redis theo key.
       - Dùng trong bước verify OTP/email.

     - `deleteOtp(String key)`:
       - Xóa OTP hoặc reset token khỏi Redis sau khi xác thực thành công.
       - Đảm bảo OTP/token chỉ được sử dụng **một lần**.

   - Thiết kế theo nguyên tắc:
     - OTP và token có vòng đời ngắn.
     - Không lưu trạng thái tạm trong database.
     - Redis đóng vai trò **temporary secure storage** cho authentication flow.


  1. **Test OTP Flow**  
     - Khởi chạy Redis bằng `docker-compose up`.
     - Verify thủ công bằng `redis-cli`:
       - Key được tạo đúng.
       - TTL giảm dần và tự động expire.

- **Kết quả**:
  - Kết nối Redis hoạt động ổn định.
  - OTP được lưu, xác thực và tự động hết hạn đúng như thiết kế.
  - Sẵn sàng tích hợp vào **User Registration & Email Verification flow**.

- **Tools / Tech**:
  - Spring Data Redis
  - Redis CLI
  - Docker & Docker Compose


### 2. Implement EmailService với Java Mail Sender ⏱️ 2h

- **Mô tả**:

  1. **Cấu hình Gmail SMTP (application.properties)**:
     - Không hardcode credential, sử dụng biến môi trường.
     - Áp dụng cấu hình mặc định cho Gmail SMTP với fallback value.

     ```properties
     spring.mail.host=${MAIL_HOST:smtp.gmail.com}
     spring.mail.port=${MAIL_PORT:587}
     spring.mail.username=${MAIL_USERNAME:truongchuong20@gmail.com}
     spring.mail.password=${MAIL_PASSWORD}

     spring.mail.properties.mail.smtp.auth=true
     spring.mail.properties.mail.smtp.starttls.enable=true
     ```

     - Sử dụng **Gmail App Password**.

  2. **Xây dựng EmailService**:
     - Thiết kế EmailService đơn giản, reusable cho nhiều use case.
     - Chỉ expose **một method duy nhất**:

       - `sendMail(String toEmail, String subject, String content)`:
         - `toEmail`: email người nhận.
         - `subject`: tiêu đề email.
         - `content`: nội dung email (HTML).
         - Sử dụng `MimeMessageHelper` để hỗ trợ UTF-8 và HTML content.

     - Các use case như:
       - Gửi OTP xác thực email
       - Gửi OTP reset mật khẩu  
       → được xử lý ở **Service layer khác**, EmailService chỉ chịu trách nhiệm gửi mail.

  3. **Chuẩn bị Email Content**:
     - Nội dung email được build từ Service layer (OTP / Reset Password).
     - Có thể tách ra dùng Thymeleaf template ở bước tiếp theo nếu cần mở rộng.

## 🚧 Khó khăn và giải pháp

### Vấn đề: Gmail chặn sign-in attempt từ ứng dụng Spring Boot
- **Mô tả**: Khi test `EmailService`, nhận được `MailSendException: 535-5.7.8 Username and Password not accepted`.
- **Ảnh hưởng**: Không thể test flow gửi email, block tiến độ.
- **Nguyên nhân gốc rễ**: 
  1. Gmail mặc định chặn "less secure apps". Tính năng này đã bị Google disable.
  2. Tài khoản Gmail đã bật 2FA, cần dùng "App Password" thay vì mật khẩu thông thường.
  3. Có thể cần enable "Access for less secure apps" (tùy tài khoản) hoặc phải dùng OAuth2.
- **Cách giải quyết đã áp dụng**:
  1. Truy cập [Google Account Security](https://myaccount.google.com/security).
  2. Bật 2-Step Verification nếu chưa bật.
  3. Tạo "App Password": Chọn "Mail" và "Other (Custom name)", đặt tên "EventHub Dev".
  4. Dùng 16-character password được generate thay cho mật khẩu Gmail thông thường trong `application-secret.yml`.
  5. Test lại -> thành công!
- **Kết quả sau khi giải quyết**: Email được gửi thành công từ ứng dụng local.
- **Bài học rút ra**: 
  1. Luôn dùng App Password cho applications, không dùng mật khẩu chính.
  2. Đối với production, nên dùng transactional email services (SendGrid, Amazon SES) thay vì Gmail SMTP để tránh giới hạn và tăng deliverability.
