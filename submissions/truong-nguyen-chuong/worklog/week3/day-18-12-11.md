## 💼 Công việc đã thực hiện

### 1. Hoàn thiện API Specification cho User Service ⏱️ 2.5 giờ
- **Mô tả**: Hoàn thiện thiết kế chi tiết các endpoint của User Service:
    - `POST /api/v1/user/auth/register`: Đăng ký tài khoản mới
    - `POST /api/v1/user/auth/login`: Đăng nhập hệ thống
    - `POST /api/v1/user/auth/verify-email`: Xác thực email bằng OTP
    - `POST /api/v1/user/auth/forgot-password`: Khởi tạo quy trình quên mật khẩu
    - `POST /api/v1/user/auth/verify-forgot-password`: Xác thực OTP quên mật khẩu
    - `POST /api/v1/user/auth/reset-password`: Đặt lại mật khẩu mới

- **Nhóm API User Self-Management (Authenticated APIs)**:
    - `GET /api/v1/user/auth/secure/profile`: Lấy thông tin hồ sơ người dùng hiện tại
    - `POST /api/v1/user/auth/change-password`: Thay đổi mật khẩu
    - `PATCH /api/v1/user/auth/update-info`: Cập nhật thông tin cá nhân
- **Kết quả**: Hoàn thành API spec, bao gồm request/response schema, status codes và error messages.
- **Tools/Tech**: OpenAPI 3.0, Postman, Swagger Editor

---

### 2. Thiết kế luồng xác thực OTP với Redis ⏱️ 1.5 giờ
- **Mô tả**:
  - Sinh OTP 6 chữ số ngẫu nhiên
  - Lưu OTP trong Redis với TTL 5 phút
  - Retry tối đa 3 lần nhập sai
  - Xóa OTP sau khi xác thực thành công
- **Kết quả**: Hoàn thành sequence diagram cho OTP flow và thiết kế Redis data structure.
- **Tools/Tech**: Redis, Draw.io, Spring Boot

## 🚧 Khó khăn và giải pháp

### Vấn đề: Thiết kế retry mechanism cho OTP
- **Mô tả**: Cần giới hạn số lần nhập sai OTP để chống brute force
- **Giải pháp**:
  - Redis counter với key `otp_attempts:{email}:{type}`
  - Reset counter khi OTP hợp lệ hoặc hết hạn
- **Bài học**: Luôn cân nhắc security ngay từ giai đoạn thiết kế.
