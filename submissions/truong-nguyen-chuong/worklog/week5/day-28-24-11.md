## 💼 Công việc đã thực hiện

### 1. Deep Dive: So sánh các dịch vụ Database trên AWS ⏱️ 18:00 - 19:30

- **Mô tả**:  
  Tiếp tục Module 06 từ ngày hôm trước, tập trung phân tích sâu các dịch vụ cơ sở dữ liệu chính của AWS:
  - **Amazon RDS**: MySQL, PostgreSQL, SQL Server – ưu điểm về ACID, schema rõ ràng
  - **Amazon Aurora**: Hiệu năng cao, khả năng mở rộng tốt hơn RDS truyền thống
  - **Amazon DynamoDB**: NoSQL, serverless, scale lớn, latency thấp
  
  Phân tích sự khác nhau dựa trên các tiêu chí:
  - Kiểu dữ liệu (Relational vs NoSQL)
  - Khả năng mở rộng (Vertical vs Horizontal scaling)
  - Tính nhất quán dữ liệu
  - Chi phí và độ phức tạp vận hành

- **Kết quả**:  
  Hiểu rõ **không có database “tốt nhất”**, mà chỉ có **database phù hợp nhất với bài toán cụ thể**.

- **Tools/Tech**: AWS Training Module 06, Personal notes.

### 2. Use Case Mapping: Áp dụng Module 06 vào hệ thống thực tế ⏱️ 19:30 - 21:00

- **Mô tả**:  
  Áp dụng kiến thức đã học để liên hệ với hệ thống đang xây dựng trong kỳ thực tập:
  - **User Service** → Amazon RDS (PostgreSQL)  
    - Lý do: dữ liệu có quan hệ chặt chẽ, cần transaction và tính nhất quán cao
  - **OTP / Session / Token blacklist** → ElastiCache (Redis)  
    - Lý do: truy cập nhanh, dữ liệu tạm thời, TTL rõ ràng
  - **Event logs / Activity tracking (định hướng)** → DynamoDB  
    - Lý do: ghi nhiều, truy vấn đơn giản, dễ scale

  Phân tích trade-off giữa hiệu năng – chi phí – độ phức tạp vận hành.

- **Kết quả**:  
  Hình thành tư duy **polyglot persistence** – sử dụng nhiều loại database cho các mục đích khác nhau trong cùng một hệ thống.

- **Tools/Tech**: System architecture reasoning, AWS service comparison.

---

### 3. Database Design Considerations & Best Practices ⏱️ 21:00 - 22:00

- **Mô tả**:  
  Tổng hợp các best practices quan trọng từ Module 06:
  - Không dùng database cho mọi bài toán (đặc biệt là NoSQL)
  - Sử dụng **read replica** để scale đọc
  - Kết hợp **cache (Redis)** để giảm tải database chính
  - Backup, monitoring và high availability là yếu tố bắt buộc trong production
  
  Đồng thời nhận diện các anti-pattern:
  - Dùng DynamoDB cho dữ liệu có quan hệ phức tạp
  - Bỏ qua chiến lược backup và recovery
  - Thiết kế schema mà không dựa trên access pattern

- **Kết quả**:  
  Hiểu rõ vai trò của database trong toàn bộ vòng đời hệ thống, không chỉ ở mức lưu trữ dữ liệu.

- **Tools/Tech**: AWS documentation, personal synthesis.
