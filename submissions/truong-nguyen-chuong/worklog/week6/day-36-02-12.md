## 💼 Công việc đã thực hiện

### 1. Nghiên cứu Amazon CloudFront ⏱️ 2h
- **Mô tả**:
  - Tìm hiểu CloudFront là gì và vì sao nó quan trọng cho hệ thống scale
  - Phân tích kiến trúc CDN:
    - Edge Locations
    - Origin (S3 / ALB / EC2 / Custom Origin)
  - Flow request:
    - Client → Edge Location → (Cache hit / Cache miss) → Origin
- **Tools/Tech**:
  - AWS Docs, Developer Guide
  - MDN / HTTP Caching primers
- **Links**:
  - [Amazon CloudFront Overview](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/Introduction.html)
  - [AWS Global Edge Network / Features](https://aws.amazon.com/cloudfront/features/)
- **Kết quả**: Hiểu CloudFront không chỉ tăng tốc mà còn **giảm chi phí data transfer & giảm tải origin**

---

### 2. Phân tích bài toán chi phí khi không dùng CDN ⏱️ 1h
- **Mô tả**:
  - Phân tích kịch bản:
    - Frontend gọi trực tiếp ALB / EC2 → each request hits origin
  - Vấn đề nhận diện:
    - Tăng latency, tăng chi phí data transfer (egress)
    - Origin dễ bị quá tải trong peak traffic
- **Tools/Tech**: Cost Explorer (concept), basic traffic modelling
- **Links**:
  - [CloudFront Pricing & Cost Savings](https://aws.amazon.com/cloudfront/pricing/)
- **Kết quả**: CloudFront là giải pháp kiến trúc để balance latency vs cost
- **Insight**:
  > Tối ưu chi phí cloud không đến từ dùng ít dịch vụ, mà từ việc dùng đúng tầng trong kiến trúc

---

### 3. Học về cache behavior và TTL ⏱️ 0.5h

  - Tìm hiểu Cache Key, Default/Min/Max TTL, Cache-Control headers
  - Xem mối liên hệ giữa response headers và CDN behaviour
- **Tools/Tech**: curl, browser devtools, sample S3 responses
- **Links**:

  - [HTTP caching (MDN)](https://developer.mozilla.org/en-US/docs/Web/HTTP/Caching)
- **Kết quả**: Nhận thức rằng **backend quyết định hiệu quả cache nhiều hơn CDN**
