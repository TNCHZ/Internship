### 2. Phân tích VPC Requirements ⏱️ 1.5h
- **Mô tả**: Xác định các yêu cầu về networking, security, scalability
- **Kết quả**: Danh sách chi tiết các thành phần VPC cần thiết
- **Yêu cầu Chính**:
  1. **High Availability**: 2 Availability Zones
  2. **Security**: Separate subnets cho public/private resources
  3. **Scalability**: Auto-scaling cho ECS services
  4. **Isolation**: RDS riêng biệt, không public
  5. **Outbound Traffic**: ECS cần NAT Gateway để ra ngoài
  6. **Inbound Traffic**: Người dùng → ALB → ECS
- **Services AWS cần**:
  - VPC: Virtual Private Cloud
  - Subnets: Public và Private
  - Internet Gateway: Outbound từ public subnet
  - NAT Gateway: Outbound từ ECS (private subnet)
  - Application Load Balancer: Routing từ internet → ECS
  - ECS: Container orchestration cho microservices
  - RDS: Managed PostgreSQL database
  - Route Tables: Định tuyến traffic
- **Lý do loại bỏ EC2**:
  - EC2 cần quản lý thủ công (patching, scaling, monitoring)
  - Quá nhiều dịch vụ → khó quản lý trên EC2 thông thường
  - ECS Fargate: Managed container service, auto-scaling, pay-per-use
  - Tiết kiệm chi phí hơn EC2 cho microservices
- **Tools/Tech**: AWS architecture planning, networking concepts

### 3. Thiết kế Kiến trúc VPC ⏱️ 1.5h
- **Mô tả**: Vẽ sơ đồ kiến trúc chi tiết, xác định CIDR blocks, subnets, AZs
- **Kết quả**: Kiến trúc VPC đầy đủ cho hệ thống
- **VPC Configuration**:
  ```
  VPC: 10.0.0.0/16
  ├── Availability Zone 1 (ap-southeast-1a)
  │   ├── Public Subnet: 10.0.1.0/24
  │   │   └── Resources: ALB, NAT Gateway
  │   └── Private Subnet RDS: 10.0.11.0/24
  │       └── Resources: RDS Primary
  │
  └── Availability Zone 2 (ap-southeast-1b)
      ├── Public Subnet: 10.0.2.0/24
      │   └── Resources: ALB (multi-AZ), NAT Gateway
      └── Private Subnet ECS: 10.0.12.0/24
          └── Resources: ECS Tasks (Fargate)
  ```
- **Traffic Flow**:
  1. **Inbound** (Internet → ECS):
     ```
     Internet (người dùng)
     ↓
     Internet Gateway
     ↓
     Public Subnet (route 0.0.0.0/0 → IGW)
     ↓
     Application Load Balancer
     ↓
     Private Subnet (route → ALB target group)
     ↓
     ECS Tasks (các services)
     ```
  2. **Outbound** (ECS → Internet):
     ```
     ECS Tasks (private subnet)
     ↓
     NAT Gateway (public subnet)
     ↓
     Internet Gateway
     ↓
     Internet
     ```
  3. **RDS Traffic** (ECS → RDS):
     ```
     ECS Tasks (private subnet 10.0.12.0/24)
     ↓
     Security Group Rule (allow port 5432)
     ↓
     RDS Instance (private subnet 10.0.11.0/24)
     ```
- **Route Tables**:
  - Public Route Table:
    - `10.0.0.0/16` → Local
    - `0.0.0.0/0` → Internet Gateway
  - Private Route Table:
    - `10.0.0.0/16` → Local
    - `0.0.0.0/0` → NAT Gateway
- **Security Groups**:
  - ALB SG: Inbound HTTP/HTTPS từ 0.0.0.0/0
  - ECS SG: Inbound từ ALB SG, outbound all
  - RDS SG: Inbound port 5432 từ ECS SG
- **Links**: [AWS VPC Documentation](https://docs.aws.amazon.com/vpc/latest/userguide/)

## 🚧 Vấn đề gặp phải

### Vấn đề 1: Lựa chọn EC2 vs ECS
- **Mô tả**: Ban đầu dự định dùng EC2, nhưng khó quản lý
- **Ảnh hưởng**: Phức tạp, high operational overhead
- **Cách giải quyết**: Chuyển sang ECS Fargate (managed)
- **Kết quả**: ECS phù hợp hơn cho microservices
- **Bài học rút ra**: Managed services > self-managed khi có nhiều dịch vụ

### Vấn đề 2: Thiết kế subnet phức tạp
- **Mô tả**: Không chắc cách tổ chức subnets cho các thành phần khác nhau
- **Ảnh hưởng**: Ban đầu tối nhất
- **Cách giải quyết**: Phân tích yêu cầu, vẽ sơ đồ chi tiết
- **Kết quả**: Kiến trúc rõ ràng, dễ triển khai
