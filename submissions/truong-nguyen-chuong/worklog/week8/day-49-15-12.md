### 1. Tích hợp & Cấu hình AWS S3 ⏱️ 1h
- **Mô tả**: Thiết lập S3 bucket trên AWS và cấu hình SDK
- **Kết quả**: Backend được cấu hình đầy đủ để sử dụng S3
- **Chi tiết công việc**:
  - **Thiết lập S3 Bucket**:
    - Tạo S3 bucket theo quy ước đặt tên: `app-assets-prod`
    - Cấu hình versioning cho bucket (tùy chọn nhưng được khuyến nghị)
    - Chọn storage class phù hợp (Standard cho dữ liệu truy cập thường xuyên)
    - Bật mã hóa phía server (SSE-S3)
    - Chặn toàn bộ public access (sử dụng signed URL thay thế)
  - **Cấu hình IAM**:
    - Tạo IAM user phục vụ upload lên S3
    - Gán policy: `AmazonS3FullAccess` (dùng cho môi trường development, sẽ siết quyền sau)
    - Tạo access key và secret key
    - Lưu trữ credentials an toàn (AWS Secrets Manager hoặc file `.env`)
  - **Cấu hình CORS** (phục vụ upload trực tiếp từ trình duyệt nếu cần):
    - Cho phép request PUT từ domain frontend
    - Khai báo các header được phép
    - Thiết lập thời gian cache cho preflight request
  - **Tích hợp SDK**:
    - Thêm dependency AWS SDK (ví dụ: `aws-sdk` hoặc `@aws-sdk/client-s3`)
    - Khởi tạo S3 client với credentials
    - Cấu hình region (ap-southeast-1 – Singapore)
    - Thiết lập connection pooling
  - **Xử lý lỗi**:
    - Xử lý trường hợp dịch vụ S3 không khả dụng
    - Cơ chế retry với exponential backoff
    - Trả về thông báo lỗi rõ ràng cho frontend
- **Tools/Tech**: AWS S3, AWS SDK, IAM, AWS Secrets Manager

### 2. Triển khai Backend Upload Ảnh Đại Diện ⏱️ 1.5h
- **Mô tả**: Triển khai endpoint upload file, validation và lưu trữ trên S3
- **Kết quả**: Người dùng có thể upload ảnh đại diện hồ sơ
- **Chi tiết công việc**:
  - **Endpoint Upload**: `PATCH /api/v1/user/auth/update`
    - Chấp nhận multipart form-data
    - Trích xuất file từ request body
    - Thực hiện validation file (kích thước, loại, độ phân giải)
  - **Validation File**:
    - Kích thước file: Tối đa 5MB (tránh lãng phí dung lượng)
    - Loại file: Chỉ cho phép ảnh (jpeg, png, webp, gif)
    - Kích thước ảnh: Tối thiểu 100x100, tối đa 2000x2000
    - Kiểm tra MIME type thực tế (không chỉ dựa vào phần mở rộng)
  - **Upload lên S3**:
    - Upload kèm metadata:
      - ContentType: MIME type đã phát hiện
      - Metadata: userId, thời điểm upload
      - ACL: private (truy cập thông qua signed URL)
    - Xử lý tốt các trường hợp upload đồng thời
  - **Cập nhật Database**:
    - Lưu S3 key (đường dẫn đầy đủ) vào bản ghi user
    - Lưu tên file gốc
    - Lưu thời điểm upload
    - Lưu kích thước file
  - **Response trả về**:
    - URL ảnh đại diện (signed URL hoặc CloudFront URL)
    - Thông báo xác nhận thành công
    - Dữ liệu user đã được cập nhật
  - **Xử lý lỗi**:
    - Lỗi validation: Trả về 400 kèm chi tiết
    - Lỗi upload S3: Retry hoặc fail graceful
    - Lỗi database: Rollback thao tác upload S3
    - User chưa xác thực: Trả về 401
  - **Bảo mật**:
    - Xác minh người dùng sở hữu profile (authorization)
    - Ngăn chặn truy cập đường dẫn S3 trái phép
    - Quét malware (tùy chọn, tùy theo use case)
    - Giới hạn số lần upload theo user (rate limiting)
- **Tools/Tech**: Express / Spring Boot, Multer / Multipart, AWS S3 SDK, thư viện validation file

### 3. Quản lý URL Ảnh Đại Diện & Cập Nhật Database ⏱️ 1h
- **Mô tả**: Lưu trữ URL ảnh đại diện, tạo signed URL, dọn dẹp các avatar cũ
- **Kết quả**: URL avatar được quản lý hiệu quả, file cũ được dọn dẹp gọn gàng
- **Chi tiết công việc**:
  - **Lưu trữ URL Ảnh Đại Diện**:
    - Lưu S3 key vào bảng user profile
    - Lưu thời gian hết hạn của signed URL
    - Lưu S3 key của avatar cũ để phục vụ cleanup
  - **Signed URL cho Truy Cập An Toàn**:
    - Tạo signed URL (hiệu lực 1 giờ hoặc 1 ngày)
    - Đính kèm signed URL trong response user
    - Frontend lưu và sử dụng signed URL
    - Tránh việc lộ truy cập trực tiếp tới S3
  - **CloudFront Distribution** (Tùy chọn – tối ưu hiệu năng):
    - Tạo CloudFront distribution
    - Trỏ về S3 bucket
    - Invalidate cache khi avatar được cập nhật
    - Giảm độ trễ, phân phối nội dung theo vị trí địa lý
  - **Dọn dẹp Avatar Cũ**:
    - Theo dõi các S3 key của avatar trước đó
    - Xóa avatar cũ khi upload avatar mới
    - Thiết lập S3 lifecycle policy để tự động cleanup
    - Tránh phình to dung lượng lưu trữ
  - **Cập nhật User Model**:
    - Thêm trường tính toán `avatarUrl` (tạo signed URL động)
    - Thêm timestamp upload avatar
    - Migration cho user hiện tại (giá trị mặc định là null)
  - **Đảm bảo tính nhất quán**:
    - Đảm bảo signed URL luôn khả dụng
    - Xử lý graceful khi S3 key bị xóa
    - Fallback về avatar mặc định khi cần
-**Tools/Tech**: ORM (JPA, Sequelize), S3 Signed URLs, CloudFront CDN

  - **Integration Tests**:

    - Xác minh dữ liệu được cập nhật trong database

## 🚧 Vấn đề gặp phải

### Vấn đề 1: Quản lý Credentials S3
- **Mô tả**: Làm thế nào để lưu trữ AWS credentials một cách an toàn?
- **Ảnh hưởng**: Lộ credentials = vi phạm bảo mật nghiêm trọng
- **Cách giải quyết**:
  - Sử dụng AWS Secrets Manager trong môi trường production
  - Dùng file `.env` trong môi trường development
  - Tuyệt đối không commit credentials lên git
  - Thực hiện xoay vòng key định kỳ
- **Kết quả**: Credentials được bảo mật an toàn
- **Bài học rút ra**: Quản lý secrets là một thực hành bảo mật tối quan trọng

---

### Vấn đề 2: Thời hạn Signed URL của S3
- **Mô tả**: Signed URL nên có thời gian hiệu lực bao lâu?
- **Ảnh hưởng**: Quá ngắn → người dùng không truy cập được; quá dài → rủi ro bảo mật
- **Cách giải quyết**:
  - 1 giờ cho các nhu cầu truy cập tạm thời
  - 1 ngày cho avatar hồ sơ (có cache)
  - Tạo lại signed URL theo nhu cầu (on-demand)
- **Kết quả**: Thời gian hết hạn phù hợp với từng use case
- **Bài học rút ra**: Cần cân bằng giữa bảo mật và trải nghiệm người dùng

---

### Vấn đề 3: Validation Loại File
- **Mô tả**: Không thể chỉ tin vào phần mở rộng của file
- **Ảnh hưởng**: Người dùng có thể upload file độc hại nhưng gắn đuôi `.jpg`
- **Cách giải quyết**:
  - Validate MIME type dựa trên nội dung thực của file
  - Sử dụng thư viện như `file-type` để nhận diện
  - Kiểm tra kích thước (dimensions) của ảnh
  - Tùy chọn: Quét virus bằng API antivirus
- **Kết quả**: Chỉ những file hợp lệ mới được upload
- **Bài học rút ra**: Không bao giờ tin dữ liệu từ người dùng, đặc biệt là khi upload file
