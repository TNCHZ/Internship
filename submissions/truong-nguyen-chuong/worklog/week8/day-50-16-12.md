## 💼 Công việc đã thực hiện

### 1. Thiết kế Kiến Trúc API Gateway ⏱️ 1h
- **Mô tả**: Thiết kế cấu trúc API Gateway, chiến lược routing và các mô hình tích hợp
- **Kết quả**: Kiến trúc API Gateway rõ ràng, được tài liệu hóa đầy đủ
- **Chi tiết công việc**:
  - **Mục đích của API Gateway**:
    - Điểm vào duy nhất cho tất cả các backend service
    - Xác thực / phân quyền tập trung
    - Giới hạn tốc độ (rate limiting) và throttling
    - Biến đổi request / response
    - Versioning API (ví dụ: `/v1/users`)
  - **Chiến lược Routing**:
    - `/v1/users/*` → User Service (port 8001)
    - `/v1/events/*` → Event Service (port 8002)
    - `/v1/chat/*` → AI Chat Service (port 8003)
    - `/v1/payments/*` → Payment Service (port 8004)
  - **Phương thức tích hợp**:
    - **HTTP Integration**: Backend service được expose qua HTTP endpoint
    - **Lambda Integration**: Serverless function cho các tác vụ nhẹ
    - **Transformation**: Mapping request từ API Gateway sang định dạng backend
    - **Mock Integration**: Phục vụ test khi chưa có backend
  - **Chiến lược Authorization**:
    - Sử dụng JWT token trong header `Authorization`
    - API key cho các public endpoint (tùy chọn)
    - Phân quyền theo resource
    - Validation request trước khi routing
  - **Request / Response**:
    - Chuẩn hóa format request
    - Chuẩn hóa format error response
    - Mapping mã trạng thái HTTP response
    - Cấu hình CORS
  - **Các tính năng API Gateway được sử dụng**:
    - **Throttling**: 1000 request/giây cho mỗi account
    - **Rate Limiting**: Giới hạn theo từng user
    - **Caching**: Cache response GET (TTL 5 phút)
    - **Logging**: CloudWatch Logs phục vụ debug
    - **Monitoring**: CloudWatch Metrics
    - **WAF** (Web Application Firewall): Tùy chọn, dùng để chống DDoS
- **Tools/Tech**: AWS API Gateway, CloudWatch, IAM

### 2. Thiết lập Resources và Methods API Gateway ⏱️ 1.5h
- **Mô tả**: Tạo các resources, methods, và intergration trên API Gateway để kết nối backend services
- **Kết quả**: API Gateway được cấu hình đầy đủ cho user service
- **Cách làm**:
  1. **Tạo API REST**:
     - Vào AWS API Gateway console
     - Chọn "Create API" → "REST API"
     - Đặt tên: `EventHub API`
     - Chọn region: `us-east-1`
  2. **Tạo Resources**:
     - Tạo resource `/users`
     - Tạo sub-resource `/{id}` dưới `/users`
     - Tạo resource `/profile`
     - Tạo resource `/avatar`
  3. **Tạo Methods cho từng resource**:
     - **GET /users**: Lấy danh sách người dùng (public, cache)
     - **POST /users**: Tạo người dùng mới (public, không cần auth)
     - **GET /users/{id}**: Lấy thông tin người dùng theo ID (public)
     - **PUT /users/{id}**: Cập nhật người dùng (yêu cầu auth)
     - **DELETE /users/{id}**: Xóa người dùng (yêu cầu admin)
     - **GET /profile**: Lấy profile cá nhân (yêu cầu auth)
     - **PUT /profile**: Cập nhật profile (yêu cầu auth)
     - **PUT /avatar**: Upload avatar (yêu cầu auth)
  4. **Cấu hình Integration**:
     - Chọn integration type: HTTP
     - Nhập HTTP endpoint của backend service
     - Cấu hình HTTP method (GET, POST, PUT, DELETE)
     - Thêm custom headers nếu cần
  5. **Cấu hình Request/Response Mapping**:
     - Extract path parameters và query parameters
     - Map request headers
     - Transform request body nếu cần
     - Cấu hình status code mapping (200, 400, 401, 403, 404, 500)
     - Transform response body nếu cần
  6. **Cấu hình Authorization**:
     - Chọn authorization type (NONE, AWS_IAM, Cognito, Lambda authorizer)
     - Áp dụng auth cho các protected endpoints
  7. **Cấu hình CORS**:
     - Enable CORS trên resources
     - Cấu hình allowed origins (specific domains hoặc *)
     - Cấu hình allowed methods (GET, POST, PUT, DELETE, OPTIONS)
     - Cấu hình allowed headers (Content-Type, Authorization, etc)
- **Tools/Tech**: AWS API Gateway console, CloudFormation (optional)
- **Bài học**: Cấu hình API Gateway có thể phức tạp; infrastructure-as-code giúp quản lý tốt hơn

### 3. Cấu hình Authorization và Security ⏱️ 1.5h
- **Mô tả**: Thiết lập JWT validation, API keys, request validation để bảo vệ API Gateway
- **Kết quả**: API Gateway bảo vệ các endpoints một cách thích hợp
- **Cách làm**:
  1. **Tạo Lambda Authorizer cho JWT**:
     - Vào AWS Lambda console
     - Tạo function mới (Node.js hoặc Python)
     - Logic: extract JWT token từ Authorization header
     - Validate token signature (kiểm tra với public key)
     - Kiểm tra expiration time
     - Extract claims (user ID, roles, permissions)
     - Return IAM policy (Allow hoặc Deny)
  2. **Gắn Authorizer vào API Gateway**:
     - Vào API Gateway console
     - Chọn "Authorizers"
     - Tạo authorizer mới, chọn Lambda authorizer
     - Chỉ định token source (Authorization header)
  3. **Áp dụng Authorization cho Methods**:
     - **Endpoints Public** (không cần auth):
       - GET /users
       - POST /users (đăng ký)
       - GET /users/{id}
     - **Endpoints Protected** (yêu cầu auth):
       - PUT /users/{id}
       - DELETE /users/{id}
       - GET /profile
       - PUT /profile
       - PUT /avatar
  4. **Cấu hình Rate Limiting**:
     - Vào API Gateway → API Keys
     - Tạo API key cho từng user/client
     - Tạo Usage Plan
     - Thiết lập quota: 100 requests/phút cho user
     - Thiết lập throttle: 1000 requests/phút tối đa
     - Gắn Usage Plan vào stage
  5. **Cấu hình Request Validation**:
     - Vào API Gateway → Request Validators
     - Tạo validator mới
     - Định nghĩa JSON schema cho POST/PUT requests
     - Validate required fields: name, email, age, etc
     - Validate content-type header (application/json)
     - Gắn validator vào methods
  6. **Cấu hình Response Security Headers**:
     - Thêm response headers trong Integration Response:
       - `X-Frame-Options: DENY`
       - `X-Content-Type-Options: nosniff`
       - `Content-Security-Policy: default-src 'none'`
     - Loại bỏ headers nhạy cảm (server version, etc)
  7. **Cấu hình Logging & Monitoring**:
     - Enable CloudWatch Logs:
       - Access logs: all requests
       - Execution logs: for debugging
     - Tạo CloudWatch Alarms:
       - High error rate (5xx > 5% trong 5 phút)
       - High latency (p99 > 1 second)
     - Enable X-Ray tracing: để debug end-to-end requests
     - Tạo CloudWatch Dashboard:
       - Metrics: request count, latency, error count
       - Logs Insights: query logs để debug issues
- **Tools/Tech**: Lambda, API Gateway authorizers, CloudWatch, X-Ray
- **Bài học**: Bảo vệ tại tầng API Gateway giúp bảo vệ backend services từ sự lạm dụng

## 🚧 Vấn đề gặp phải

### Vấn đề 1: Khám phá vị trí Backend Service
- **Mô tả**: API Gateway cần khám phá vị trí các backend services
- **Ảnh hưởng**: Hardcoding IPs/hostnames không linh hoạt
- **Cách giải quyết**: 
  - Sử dụng service DNS names (e.g., user-service.internal)
  - Biến môi trường cho URLs services
  - Service discovery tools (Consul, Eureka) - tương lai
- **Kết quả**: Service routing linh hoạt
- **Bài học**: Cần abstractions cho hệ thống phân tán

### Vấn đề 2: Cấu hình Request Timeout
- **Mô tả**: API Gateway nên chờ backend bao lâu?
- **Ảnh hưởng**: Quá ngắn = timeouts; quá dài = latency cao
- **Cách giải quyết**: 
  - 30 giây mặc định (giới hạn AWS)
  - Ngắn hơn cho các tác vụ nhẹ (5s)
  - Dài hơn cho các tác vụ nặng (có thể async)
- **Kết quả**: Timeouts thích hợp được cấu hình
- **Bài học**: Timeouts rất quan trọng cho khả năng phục hồi

### Vấn đề 3: Hiệu suất JWT Authorizer
- **Mô tả**: JWT validation trên mỗi request có thể chậm
- **Ảnh hưởng**: Latency được thêm vào cho tất cả requests
- **Cách giải quyết**: 
  - Cache kết quả JWT validation
  - API Gateway caches authorizer response
  - Hoặc sử dụng API keys cho overhead thấp hơn
- **Kết quả**: Latency xác thực chấp nhận được
- **Bài học**: Cache tại tầng gateway cải thiện hiệu suất
