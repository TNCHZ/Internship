### 1. Tối ưu hóa & Cải thiện Docker Compose ⏱️ 1h
- **Mô tả**: Tối ưu hóa Docker compose file, cải thiện quá trình build
- **Kết quả**: Cấu hình Docker compose sẵn sàng cho production
- **Chi tiết công việc**:
  - **Cấu trúc Docker Compose**:
    - Container User Service
    - Container PostgreSQL database
    - Container Redis cache
    - Quản lý biến môi trường
    - Quản lý volumes để lưu giữ dữ liệu
  - **Chiến lược Tối ưu hóa**:
    - **Multi-stage builds**: Tách giai đoạn build từ runtime
    - **Layer caching**: Sắp xếp lệnh Dockerfile để tối đa hóa cache hits
    - **Giảm kích thước image**: Giảm thiểu layers, sử dụng alpine base images
    - **Dependencies**: Chỉ bao gồm production dependencies
    - **Bảo mật**: Chạy với non-root user
  - **Thiết lập Database**:
    - PostgreSQL service với custom config
    - Tạo database và schema ban đầu
    - Volume để lưu giữ dữ liệu
    - Health checks để đảm bảo sẵn sàng
  - **Thiết lập Cache**:
    - Redis service cho session và query caching
    - Memory limits để tránh OOM
    - Cấu hình persistence
  - **Cấu hình Môi trường**:
    - Database connection strings
    - Redis connection details
    - AWS credentials cho S3 access
    - JWT secret keys
    - Separate .env files cho các môi trường khác nhau
  - **Networking**:
    - Internal Docker network cho service communication
    - Port mappings cho local development
    - Health checks cho dependent services
  - **Best Practices**:
    - Explicit version pinning (không dùng 'latest' tags)
    - Resource limits (CPU, memory)
    - Proper signal handling để graceful shutdown
    - Logging configuration
- **Tools/Tech**: Docker, Docker Compose, multi-stage builds
- **Bài học**: Docker optimization có ảnh hưởng đáng kể đến build times và image size

### 2. Build Docker Image & Đẩy lên ECR ⏱️ 1.5h
- **Mô tả**: Build user-service Docker image, đẩy lên AWS ECR
- **Kết quả**: Docker image trong ECR, sẵn sàng để deploy
- **Chi tiết công việc**:
  - **Thiết lập ECR Repository**:
    - Tạo ECR repository: `user-service`
    - Repository naming: `<account-id>.dkr.ecr.ap-southeast-1.amazonaws.com/user-service`
    - Enable image scanning
    - Cấu hình lifecycle policies (keep last 10 images)
    - Enable encryption
  - **Build Docker Image**:
    - `docker build -t user-service:latest .`
    - Tag với version: `user-service:1.0.0`
    - Tag với ECR registry: `<account-id>.dkr.ecr.ap-southeast-1.amazonaws.com/user-service:latest`
    - Image size optimization (target < 500MB)
    - Build time chấp nhận được (< 5 min)
  - **Đẩy lên ECR**:
    - Authenticate Docker to ECR: `aws ecr get-login-password`
    - `docker login` sử dụng credentials
    - `docker push <registry>/user-service:latest`
    - `docker push <registry>/user-service:1.0.0`
    - Verify image trong ECR console
  - **Chiến lược Image Tagging**:
    - `latest`: Luôn trỏ đến build mới nhất
    - `v1.0.0`: Semantic version tags
    - `staging`, `prod`: Environment-specific tags
    - Cho phép rollback dễ dàng về versions trước
  - **Image Scanning**:
    - ECR scans cho vulnerabilities
    - Review scan results
    - Update base image nếu tìm thấy vulnerabilities
    - Cấu hình alerts cho critical vulnerabilities
  - **Verification**:
    - Pull image từ ECR: `docker pull <registry>/user-service:latest`
    - Verify image runs correctly
    - Check image size và layers
    - Performance metrics chấp nhận được
- **Tools/Tech**: Docker, AWS ECR, AWS CLI, IAM authentication
- **Bài học**: ECR với image scanning thêm security; lifecycle policies giảm storage costs

### 3. Kiểm tra Local với Tích hợp API Gateway ⏱️ 1h
- **Mô tả**: Kiểm tra web application cục bộ sử dụng AWS API Gateway
- **Kết quả**: End-to-end flow được kiểm tra: Web → API Gateway → User Service
- **Chi tiết công việc**:
  - **Thiết lập Local**:
    - Start Docker compose stack: `docker-compose up`
    - Chờ health checks (databases ready)
    - Verify services accessible:
      - User Service: `http://localhost:8001`
      - PostgreSQL: `localhost:5432`
      - Redis: `localhost:6379`
  - **Cấu hình Frontend**:
    - Cấu hình API endpoint để sử dụng API Gateway URL
    - Example: `https://<api-gateway-id>.execute-api.ap-southeast-1.amazonaws.com/prod`
    - Không phải localhost:8001, mà là thực tế API Gateway
    - Điều này tests real integration pattern
  - **Các kịch bản Kiểm tra**:
    - **Đăng ký người dùng**:
      - Submit registration form
      - Verify API Gateway routing to user-service
      - Verify user được tạo trong database
      - Verify password hashed securely
    - **Đăng nhập người dùng**:
      - Submit login form
      - Verify JWT token returned
      - Verify token valid và usable
      - Verify subsequent requests include token
    - **Upload Avatar**:
      - Upload image via form
      - Verify routed to API Gateway
      - Verify pushed to S3
      - Verify avatar URL returned
      - Verify avatar displayed trong profile
    - **Cập nhật Profile**:
      - Update user information
      - Verify changes persisted
      - Verify chỉ owner có thể update
  - **Kịch bản Lỗi**:
    - Duplicate email registration → 400/409 error
    - Login với wrong password → 401 error
    - Unauthorized avatar upload → 401 error
    - Expired token → 401 error
  - **Kiểm tra Hiệu suất**:
    - Measure response times
    - Track request latency through API Gateway
    - Identify bottlenecks:
      - API Gateway overhead
      - Network latency
      - Database queries
      - S3 upload time
    - Acceptable ranges:
      - Simple requests: < 200ms
      - File uploads: < 5s (depends on size)
  - **Logging & Debugging**:
    - Check Docker container logs
    - Check API Gateway CloudWatch logs
    - Check backend service logs
    - Trace request path từ frontend to backend
    - Use API Gateway X-Ray tracing
  - **Browser DevTools Testing**:
    - Network tab: Verify requests hitting API Gateway
    - Headers: Verify Authorization header present
    - Cookies: Verify secure HTTP-only cookies
    - Performance: Measure response times
- **Tools/Tech**: Docker Compose, Postman, Browser DevTools, AWS CloudWatch
- **Bài học**: Integration testing rất cần thiết; thực tế API Gateway behavior thường khác với local mocks

## 🚧 Vấn đề gặp phải

### Vấn đề 1: Docker Image Build Times
- **Mô tả**: Build image mất quá lâu (> 10 min)
- **Ảnh hưởng**: Slow feedback loop, chán nản
- **Cách giải quyết**: 
  - Tối ưu hóa layer caching
  - Chuyển frequently-changed layers xuống dưới
  - Sử dụng .dockerignore để loại bỏ unnecessary files
  - Xem xét pre-built base images
- **Kết quả**: Build time < 3 minutes
- **Bài học**: Build performance quan trọng cho development velocity

### Vấn đề 2: ECR Authentication
- **Mô tả**: Docker push to ECR yêu cầu repeated authentication
- **Ảnh hưởng**: Tedious manual process, dễ quên
- **Cách giải quyết**: 
  - Automate với GitHub Actions
  - Cache credentials locally
  - Sử dụng IAM roles cho EC2 instances
- **Kết quả**: Automated push to ECR
- **Bài học**: Automation giảm manual errors

### Vấn đề 3: Local API Gateway Testing
- **Mô tả**: Kiểm tra đối với thực tế API Gateway trong AWS, không phải local mock
- **Ảnh hưởng**: Thực tế behavior có thể khác từ local testing
- **Cách giải quyết**: 
  - Luôn kiểm tra đối với thực tế API Gateway
  - Sử dụng CloudWatch logs để debug
  - Giữ API Gateway URL trong environment variables
- **Kết quả**: Confidence trong production behavior
- **Bài học**: Real integration testing rất cần thiết
