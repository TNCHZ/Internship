## 💼 Những việc hoàn thành

### 1. Đưa Frontend lên AWS S3 ⏱️ 18:00 - 19:00

- **Chi tiết**: Tạo S3 bucket mới (như: `my-event-platform-frontend`) để lưu giữ những file tĩnh từ Frontend (output của Next.js). Đã kiểm tra bucket policy nhằm cho phép CloudFront truy cập tài nguyên.
- **Kết quả đạt được**: Build Frontend đã được gửi lên S3 và có thể truy cập qua URL của S3.
- **Công cụ/Công nghệ sử dụng**: AWS S3 Console, Next.js, `aws s3 sync`.

### 2. Thiết lập AWS CloudFront Distribution ⏱️ 19:30 - 21:00

- **Chi tiết**: Tạo CloudFront Distribution, dùng S3 bucket làm nguồn gốc. Điều chỉnh Cache Behaviors để thích hợp với các file tĩnh (HTML, CSS, JS, ảnh) và kết nối qua Origin Access Control (OAC) để bảo vệ S3. Kiểm tra truy cập thông qua URL của CloudFront.
- **Kết quả đạt được**: Frontend được phân phối thông qua CloudFront, giúp tăng tốc độ tải và bảo mật tốt hơn.
- **Công cụ/Công nghệ sử dụng**: AWS CloudFront Console.

### 3. Khởi động cấu hình GitHub Actions cho Deployment Frontend ⏱️ 21:00 - 22:00

- **Chi tiết**: Tạo file workflow `.github/workflows/frontend-deploy.yml` với các bước: build Next.js, sử dụng `aws-cli` để đẩy file build lên S3 và xóa cache CloudFront khi push code vào nhánh `main`. Đã lưu AWS credentials vào GitHub Secrets (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`).
- **Kết quả đạt được**: Workflow cơ bản sẵn sàng, có thể bắt tay kiểm thử quy trình deployment tự động.
- **Công cụ/Công nghệ sử dụng**: GitHub Actions, YAML, Next.js, `aws-cli`.

### 🔧 Kỹ năng chuyên môn

### 💡 Lý thuyết và khái niệm

- **CDN (Content Delivery Network)**: Vai trò của CDN trong phân tán nội dung tĩnh, giảm độ trễ và tăng tốc độ.
- **Infrastructure as Code (IaC) (suy nghĩ ban đầu)**: Bắt đầu lên kế hoạch tự động hóa toàn bộ hạ tầng sau này.
- **Bảo mật Best Practices**: Sử dụng OAC với CloudFront để chặn truy cập trực tiếp S3.

## 🚧 Những thách thức gặp phải và cách xử lý

### Thách thức 1: Vấn đề invalidation cache CloudFront khi cập nhật Frontend

- **Mô tả**: Sau khi gửi phiên bản Frontend mới lên S3, người dùng vẫn thấy phiên bản cũ vì CloudFront lưu cache.
- **Tác động**: Người dùng không nhìn thấy được các cập nhật tân trang, gây khó chịu và trải nghiệm kém.
- **Nguyên nhân sâu xa**: Bỏ sót bước invalidation cache trên CloudFront.
- **Biện pháp đã thực hiện**: Thêm lệnh `aws cloudfront create-invalidation` vào cuối workflow GitHub Actions sau khi gửi file lên S3. Đảm bảo xóa cache cho `/` hoặc `/*` để làm tươi tất cả bộ nhớ đệm.
- **Kết quả sau xử lý**: Các thay đổi Frontend hiển thị tức thì sau mỗi lần deploy tự động.
- **Bài học**: Luôn ghi nhớ rằng bộ nhớ đệm CDN là phần không thể tách rời của quy trình triển khai Frontend và phải được quản lý hợp lý.
