## 💼 Những việc hoàn thành

### 1. Hoàn thành và Test GitHub Actions cho Frontend ⏱️ 18:00 - 20:00

- **Chi tiết**: Điều chỉnh workflow `frontend-deploy.yml` trên GitHub Actions. Bổ sung các bước để cài Node.js, cài dependencies, thực thi build Next.js, sau đó gửi kết quả build lên S3 và tạo invalidation cho CloudFront. Đặc biệt, đã thiết lập `configure-aws-credentials` action với OIDC (OpenID Connect) thay vì `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` để tăng cường bảo mật và tránh lưu trữ thông tin xác thực nhạy cảm trực tiếp trong GitHub Secrets. Đã thực hiện nhiều lần push code để test workflow.
- **Kết quả đạt được**: Frontend deployment tự động hoàn toàn qua GitHub Actions hoạt động ổn định. Mỗi lần push lên nhánh `main` sẽ tự động build, deploy và xóa cache.
- **Công cụ/Công nghệ sử dụng**: GitHub Actions, YAML, IAM Roles, AWS S3, AWS CloudFront, Next.js.

### 2. Thiết lập IAM Role và Policies cho GitHub Actions ⏱️ 20:00 - 21:00

- **Chi tiết**: Tạo một IAM Role mới trong AWS, thiết lập trust policy để cho phép GitHub Actions assume role thông qua OIDC. Gắn các IAM Policies cần thiết cho role (ví dụ: `s3:PutObject`, `s3:DeleteObject`, `s3:GetObject` trên S3 bucket; `cloudfront:CreateInvalidation` cho CloudFront). Điều này giúp GitHub Actions có thể thực hiện các hành động cần thiết mà không cần credentials lâu dài.
- **Kết quả đạt được**: IAM Role được cấu hình đúng, cấp đủ quyền cho GitHub Actions mà vẫn tuân thủ nguyên tắc đặc quyền tối thiểu (least privilege).
- **Công cụ/Công nghệ sử dụng**: AWS IAM Console, OIDC.

### 3. Cấu hình Route53 cho tên miền đã đăng ký ⏱️ 21:00 - 22:00

- **Chi tiết**: Mua một tên miền (placeholder: `myeventplatform.com`). Trong Route53, tạo một hosted zone cho tên miền này. Tạo một Alias record (A record) để trỏ `www.myeventplatform.com` và `myeventplatform.com` đến CloudFront Distribution của Frontend.
- **Kết quả đạt được**: Frontend có thể truy cập được qua tên miền riêng, mang lại cảm giác chuyên nghiệp hơn.
- **Công cụ/Công nghệ sử dụng**: AWS Route53 Console, Custom Domain.

## 📚 Những kiến thức tìm hiểu được

### 🔧 Kỹ năng chuyên môn

- **Dịch vụ AWS**: IAM (Roles, Policies, OIDC), Route53 (hosted zones, Alias records).
- **DevOps**: Thiết lập CI/CD pipeline hoàn chỉnh cho Frontend với GitHub Actions và AWS.

### 💡 Lý thuyết và khái niệm

- **OIDC (OpenID Connect)**: Nắm cách OIDC hoạt động để xác thực và ủy quyền giữa GitHub Actions và AWS IAM.
- **DNS Propagation**: Hiểu thời gian cần thiết để các thay đổi DNS được cập nhật trên toàn cầu.
- **Least Privilege Principle**: Áp dụng nguyên tắc bảo mật cơ bản này khi cấp quyền IAM.

### 🤝 Kỹ năng mềm

- **Chú ý đến chi tiết**: Thiết lập IAM và Route53 đòi hỏi sự cẩn thận để tránh sai sót.
- **Kiên nhẫn**: Gặp vài lỗi nhỏ về quyền IAM nhưng đã kiên trì tìm hiểu và xử lý.

## 🚧 Những thách thức gặp phải và cách xử lý

### Thách thức 1: Lỗi IAM permission khi GitHub Actions cố deploy

- **Mô tả**: Khi workflow GitHub Actions chạy, gặp lỗi "Access Denied" khi cố upload file lên S3 hoặc tạo invalidation cho CloudFront.
- **Tác động**: Quá trình triển khai tự động bị dừng lại.
- **Nguyên nhân sâu xa**: IAM Role được thiết lập cho GitHub Actions thiếu một số quyền cần thiết (`s3:PutObject` hoặc `cloudfront:CreateInvalidation`).
- **Biện pháp đã thực hiện**: Kiểm tra log của GitHub Actions để xác định chính xác hành động nào bị từ chối. Sau đó, chỉnh sửa IAM Policy gắn với Role, bổ sung quyền cần thiết cho các tài nguyên cụ thể (S3 bucket, CloudFront Distribution ID).
- **Kết quả sau xử lý**: Workflow chạy thành công và Frontend được triển khai tự động.
- **Bài học**: Khi xử lý lỗi IAM, luôn kiểm tra log chi tiết để nhận diện chính xác quyền thiếu và chỉ cấp những quyền tối thiểu cần thiết.

### Thách thức 2: Tên miền không trỏ đúng về CloudFront

- **Mô tả**: Sau khi cấu hình Alias record trong Route53, tên miền vẫn không tải được Frontend qua CloudFront.
- **Tác động**: Người dùng không thể truy cập Frontend qua tên miền riêng.
- **Nguyên nhân sâu xa**: Thời gian DNS propagation chưa đủ hoặc có sai sót nhỏ trong cấu hình CNAME/Alias record.
- **Biện pháp đã thực hiện**: Kiên nhẫn đợi thêm một khoảng thời gian (khoảng 30 phút). Đồng thời, kiểm tra lại Alias Target trong Route53 để chắc chắn đã chọn đúng CloudFront Distribution.
- **Kết quả sau xử lý**: Tên miền đã trỏ thành công về CloudFront và Frontend hoạt động bình thường.
- **Bài học**: DNS propagation cần thời gian. Luôn kiểm tra kỹ các giá trị trong Alias/CNAME record.
