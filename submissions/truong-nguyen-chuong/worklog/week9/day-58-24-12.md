## 💼 Công việc đã thực hiện

### 1. Phân tích và Thiết kế Luồng Inbound Traffic ⏱️ 18:00 - 19:00

- **Mô tả**: Thực hiện phân tích chi tiết cách người dùng và client applications sẽ truy cập vào backend services. Xác định các điểm vào (entry points) chính cho API và thiết lập nguyên tắc: không có ECS service nào được expose trực tiếp ra Internet. Tất cả các request phải đi qua ít nhất một lớp trung gian để kiểm soát và bảo mật.
- **Kết quả**: Xác định được kiến trúc layered security rõ ràng với các lớp public-facing và private services được phân tách biệt.
- **Tools/Tech**: AWS VPC Design, Security Groups, Network ACLs

### 2. Thiết kế API Gateway Layer ⏱️ 19:00 - 20:00

- **Mô tả**: Thiết kế lớp API Gateway đứng trước Application Load Balancer (ALB). API Gateway sẽ đảm nhận các nhiệm vụ của API management layer:
  - **Authentication & Authorization**: Xác thực request trước khi chuyển tiếp
  - **Rate Limiting**: Giới hạn request rate để bảo vệ backend
  - **Request Validation & Transformation**: Kiểm tra và chuyển đổi request format
  - **Logging & Monitoring**: Ghi log tập trung cho tất cả API calls
- **Kết quả**: Backend ECS services chỉ cần tập trung vào business logic, không phải xử lý các cross-cutting concerns.
- **Key Insight**: Phân biệt rõ ràng: API Gateway quản lý API (API management), ALB phân phối traffic (traffic distribution).
- **Tools/Tech**: AWS API Gateway, OpenAPI/Swagger specifications

### 3. Thiết kế Application Load Balancer cho ECS Services ⏱️ 20:00 - 21:00

- **Mô tả**: Thiết kế cấu hình ALB đặt trong public subnets của VPC. Các ECS services (Page Service, AIChat Service) sẽ đăng ký với ALB thông qua ECS service discovery hoặc target groups. Cấu hình:
  - **Listeners**: HTTPS listener trên port 443
  - **Target Groups**: Mỗi service có target group riêng
  - **Routing Rules**: Path-based routing (`/api/pages/*`, `/api/chat/*`)
  - **Health Checks**: Cấu hình health checks để ALB tự động loại bỏ unhealthy tasks
- **Kết quả**: Tạo được cơ chế load balancing và service discovery linh hoạt, hỗ trợ scaling dễ dàng.
- **Security**: Chỉ ALB được phép giao tiếp với ECS services thông qua security groups. ECS services chỉ listen trên private network.
- **Tools/Tech**: AWS ALB, ECS Service Discovery, Target Groups

### 4. Vẽ Sơ đồ Kiến trúc Tổng thể ⏱️ 21:00 - 22:00

- **Mô tả**: Tổng hợp tất cả các thành phần đã thiết kế vào một sơ đồ kiến trúc hoàn chỉnh. Sơ đồ bao gồm:
  - **Public Zone**: CloudFront, API Gateway, ALB (trong public subnets)
  - **Private Zone**: ECS services, RDS database (trong private subnets)
  - **Luồng dữ liệu**: Mũi tên thể hiện chiều và loại traffic (HTTP/HTTPS, database connections)
  - **Security Boundaries**: Thể hiện rõ các security groups và network ACLs
- **Kết quả**: Có được một bản visual hoàn chỉnh của kiến trúc hệ thống, dễ dàng để trình bày và thảo luận.
- **Tools/Tech**: draw.io, Lucidchart, AWS Architecture Icons

## 🚧 Khó khăn và giải pháp

### Vấn đề: Quyết định giữa ALB trực tiếp từ Internet hay qua API Gateway

- **Mô tả**: Phải quyết định xem nên để ALB nhận traffic trực tiếp từ Internet hay đặt API Gateway phía trước ALB. Mỗi cách có ưu nhược điểm khác nhau về cost, performance, và features.
- **Ảnh hưởng**: Ảnh hưởng đến kiến trúc tổng thể, chi phí vận hành, và khả năng quản lý API.
- **Nguyên nhân gốc rễ**: Cần cân bằng giữa tính năng (API management features) và độ phức tạp/thêm một hop mạng.
- **Cách giải quyết đã áp dụng**:
  1. Liệt kê các requirements: cần authentication, rate limiting, API versioning?
  2. Đánh giá cost: API Gateway có cost per request, ALB có cost per hour + LCU
  3. Xem xét team expertise: team đã quen với API Gateway hay ALB configuration?
  4. Quyết định: Sử dụng API Gateway cho các API management features quan trọng, chấp nhận thêm một hop và cost
- **Kết quả sau khi giải quyết**: Chọn kiến trúc có API Gateway, với documentation rõ ràng về lý do và các trade-offs đã cân nhắc.
- **Bài học rút ra**: Không có giải pháp "tốt nhất" tuyệt đối, chỉ có giải pháp "phù hợp nhất" cho ngữ cảnh cụ thể (requirements, constraints, team skills).

## 💭 Suy ngẫm & Nhận thức

### Hôm nay có gì diễn ra tốt đẹp?

- Đã làm rõ được kiến trúc phân tầng cho inbound traffic, một phần quan trọng của hệ thống
- Hiểu sâu hơn về sự khác biệt và bổ trợ giữa API Gateway và ALB
- Có được bản vẽ kiến trúc tổng thể rõ ràng, giúp dễ dàng truyền đạt ý tưởng

### Cần cải thiện điều gì?

- Cần tìm hiểu thêm về các advanced features của API Gateway như usage plans, API keys management
- Nên nghiên cứu các pattern cho service-to-service communication trong private network (ngoài ALB)

### Thông tin chi tiết chính

- Kiến trúc tốt không chỉ giúp hệ thống chạy được mà còn phải dễ bảo vệ (security), dễ mở rộng (scalability), và dễ vận hành (operability)
- Mỗi layer trong kiến trúc nên có một trách nhiệm rõ ràng và duy nhất (Single Responsibility Principle áp dụng cho kiến trúc)

### Câu hỏi & Thắc mắc

- Khi nào thì nên sử dụng Network Load Balancer (NLB) thay vì Application Load Balancer (ALB) cho microservices?
- Có nên sử dụng AWS WAF (Web Application Firewall) phía trước API Gateway không, và ở layer nào là phù hợp?
